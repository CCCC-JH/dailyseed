# DailySeed · 视觉规范（2026-10-11 定稿）

> **这份文件是"改样式时的判据"，不是灵感板。** 它把界面里**能判定**的部分定下来：
> 颜色语义与达标值、字号阶梯、圆角/间距/动效令牌、布局断点、触控尺寸。
>
> **改 `src/styles/**` 或 `components/Icon.tsx` 之前，先跑一遍：**
> ```powershell
> python tools/verify_redlines.py --style --selftest
> ```
> 它会量：对比度（WCAG AA）、调色板有没有漂、字号有没有出阶梯、圆角有没有绕过令牌。
> **它管不了审美判断**（构图、留白、语气、"巧思"仍然只能人看）——那条边界在 §9 写清楚了。

### 1.2 规则

1. **只有两个彩色**：`--seed`（生长）与 `--harvest`（收获/难度）。其余全是绿灰中性阶。想加第三种彩色 = 改产品气质，先讨论。
2. **小字必须 ≥ 4.5:1**。判定要用**最暗的那块底**：`--ink-3` 的有效底是 `--bg-deep`（4.53），不是 `--bg`（4.87）——取值的约束来自最紧的一处。
3. **不允许"和某个令牌只差 1–2/255"的一次性色**。那是同一件事写了两遍的指纹（实测清掉过 `#eeeee3/#eeeee4/#eeeee5` 三个只差 1/255 的"白"）。
4. 令牌外的不透明色必须在 `verify_redlines.py` 的 `OPAQUE_ALLOWED` 里，**且每条要写理由**（当前只有 4 条：警示/正常 toast 底 + CSS 画的陶土盆三色）。
5. **浅色主题的阴影用带色相的暗色**（`--shadow-ink #344c35` / `#344c3510`），不用纯黑——纯黑在米白底上会发灰发脏。

## 2. 字号阶梯（15 档 + 一个 clamp）

| 档 | 用在哪 |
| --- | --- |
| 9 | 极小的角标（`.brand__english`、`.pot__ready`） |
| 10 | `.kicker`（页面/卡片的小标签） |
| 11 | 底部导航标签、`.pot__category`、日期（窄屏） |
| 12 | `.chip`、`.daily-note`、`.section-head span` |
| **13** | 主力小字：`.muted`、`.pot__text`、`.why`、次级说明（**用得最多**） |
| 14 | `.btn`（窄）、`.row__label`、签名行 |
| **15** | 页面正文/按钮主力（`.lede`、`.btn`、`.today__next`） |
| 16 | 侧栏那句衬线短句、`.trail__text` |
| 19 / 21 / 22 / 23 | 弹层标题 / 卡背 kicker / 品牌名 / 卡背正文 |
| 25 / 27 / 30 | 同步码 / 页面标题（窄屏）/ 卡面文案 |
| `clamp(28px, 4vw, 38px)` | 页面 `<h1>` |

**规则**

1. **只允许整数**。半像素档位（11.5/12.5/13.5/14.5/15.5）2026-10-11 已全部进位并掉（20 档 → 15 档）；
   再写半像素会被 `--style` 拦下。新增档位要**先在 `FONT_SCALE` 里加一行**——这一步是故意的。
2. 字号不能替代字重/颜色来做层级：层级用 `--ink / --ink-2 / --ink-3` 表达。
3. 衬线（`--serif`）只给"会让人停一下"的句子：页面 `<h1>`、卡背 kicker、签名行、侧栏那句。**操作性文字一律无衬线。**

## 3. 圆角 / 间距 / 动效

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--r-sm` | 12px | 按钮、页签、小卡 |
| `--r-md` | 18px | 面板、列表卡 |
| `--r-lg` | 24px | 主卡、底部弹层上沿 |
| `--r-pill` | 999px | chip、圆点按钮 |
| `--pad` | 24px（≤420px 时 20px） | 页面左右留白 |
| `--tabbar` | 76px | 底部导航高度（内容要给它留位） |
| `--t-fast` / `--t-base` / `--t-slow` | 160 / 260 / 420ms | 反馈 / 常规 / 入场 |
| `--ease` | `cubic-bezier(.22,.61,.36,1)` | 主缓动（21 处引用） |

`border-radius` 要么走 `var(--r-*)`，要么是白名单里的有机形状（`50%` 圆点、盆/叶/碟那三个不规则圆角）。
`@media (prefers-reduced-motion: reduce)` 必须保持全局降级。

## 4. 布局与断点

| 断点 | 变化 |
| --- | --- |
| `≤420px` | `--pad` 20px、卡片 `min-height` 370px、插画 210px、窗台两列、日期 11px |
| `700px+` | 弹层从底部抽屉变**居中对话框**（`.mask` 居中、`.sheet` 四角圆） |
| `960px+` | 出现 240px 左侧栏（`.navigation`）、`.view` 820/850px 居中、卡片 `min-height` 440px、插画 300px |

**两条硬约束**

1. **卡背与卡面同高**：`.cardback` 与 `.today__card` 的 `min-height` 必须**成对改**（400 / 440 / ≤420px 的 370），
   否则翻面动画会在末段"跳一下"。
2. **触控目标 ≥ 44px**：按钮、`.why`、关闭按钮、chip 都按 44 算。

## 5. 图标与插画

- `components/Icon.tsx`：线条图标统一 `stroke-width 1.6`、`currentColor`（跟着文字变色）、`aria-hidden`。
  **不引图标库、不发外部请求。**
- 插画有两套，**各自内部一致即可，不要求跨渲染方式对齐**：
  - CSS 画的盆（`.pot__bowl / .pot__saucer`）：`#d69b79 → #b57758`、碟 `#d5cbb9`
  - SVG 手绘（`SeedIllustration`）：`#bc775a / #ce8c6b / #dbd4c1`，叶 `#7c9364 / #3f6249 / #a5af7c`
- 装饰性图形的对比度**按 WCAG 1.4.11 豁免**（它们不承载信息、且 `aria-hidden`）。
  但**一旦某个图标变成唯一的信息载体，就必须 ≥3:1**。

## 6. 字号/颜色的"改动流程"

1. 改之前先想清楚它属于**哪个语义**（是 `--ink-3` 还是新的东西？）。
2. 若是新颜色：想清楚语义 → 加令牌 → 若是一次性装饰色，加进 `OPAQUE_ALLOWED` 并写理由。
3. 跑 `python tools/verify_redlines.py --style --selftest`。
4. 跑 `cd frontend; npm run build`（要在**普通终端**里，受限沙箱跑不了 esbuild）。
5. 人眼看一遍：`cd frontend; npm run preview` → `http://localhost:4173`。

## 7. 为什么这些能机器判定（也就是这套规范的可信度来源）

同一套判据在 `tools/verify_redlines.py --style` 里，9 条断言 + 7 条自检：

| 断言 | 判据 |
| --- | --- |
| 对比度 ×4 组 | 正文/次级/三级 · 三级在**最暗的底**上 · 交互色 · 难度 chip，全部 ≥4.5:1 |
| 调色板 ×2 | 没有与令牌差 ≤2/255 的一次性色 · 令牌外的不透明色都在白名单里 |
| 字号 ×1 | 只用 `FONT_SCALE` 里的 15 档 |
| 圆角 ×1 | 要么 `var(--r-*)`，要么在 `RADIUS_ALLOWED` 里 |
| 产物同步 ×1 | dist 的 CSS 里能读到当前令牌值（改了样式忘了 build 会被抓到） |

自检里有两组正反例：`#000 on #fff` 必须是 21:1、同色必须是 1:1（防止公式写反）、
差 1/255 必须被抓到、差 40/255 必须放过（防止阈值写成"永远报"）。

> ⚠️ 两个实测过的**假结论**，都写进脚本注释了：
> ① 扫描颜色前**必须剥掉 CSS 注释**——注释里写"原来是 #73776b"会被当成"这个色还在用"，修完仍然报错（假失败）；
> ② 自检行的判据是 `bool(hits) == want_hit`，而**非空列表恒为真**——写成 `[False]` 会让自检空转（第一版就是这么错的）。

## 8. 这份规范**不管**什么

- **构图与留白比例**（比如"桌面端卡片空旷"是判断，不是断言）
- **语气与文案**（红线 2 那条只能人读）
- **动效的手感**（节奏快慢、翻面是否"有呼吸"）
- **色彩的情绪**（暖到什么程度、绿得是否"太卫生"）
- **平台差异**：`--serif` 在中文 Windows 上落到**宋体**，大标题是"书页感"还是"过时"，只能在真机/真屏幕上看

这些留给眼睛。**规范能保证的是"不难看且看得清"的下限，不是上限。**
